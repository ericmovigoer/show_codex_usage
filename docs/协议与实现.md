# 协议与实现

## 进程和通信

程序使用 MFC 普通对话框呈现数据，后台线程负责连接、查询、JSON 解析和刷新调度。界面通过窗口消息读取后台保存的最新快照；消息不携带需要界面释放的裸指针。

后台以隐藏的 Windows PowerShell 启动 `codex app-server`，通过标准输入和标准输出交换 UTF-8、按行分隔的 JSON 消息。接收端支持一条消息分多次读取，也支持一次读取包含多条消息，并按请求编号匹配响应；标准错误由独立线程持续排空。

启动的 PowerShell 与 Codex 子进程归属一个 Windows Job Object。程序关闭时停止调度、结束该进程树、等待读取线程退出，再回收句柄。程序只管理自己启动的进程。

## 只读调用

握手顺序为发送 `initialize` 请求、等待成功响应、发送 `initialized` 通知，之后调用：

```json
{"id":2,"method":"account/rateLimits/read","params":{"excludeResetCreditDetails":true}}
```

普通轮询使用 `excludeResetCreditDetails: true`，读取额度和重置次数；完整查询改为 `false`，同时读取重置明细。

程序不会调用创建会话、发起模型请求或兑换重置次数的接口。认证由本机 Codex CLI 处理，程序不读取和保存登录凭据。

协议字段按 Codex CLI **0.169.0** 适配，参考官方固定版本的 [GetAccountRateLimitsParams](https://github.com/openai/codex/blob/rust-v0.169.0/codex-rs/app-server-protocol/schema/typescript/v2/GetAccountRateLimitsParams.ts) 及同目录生成的 v2 类型。后续 CLI 若删除方法、改变参数或字段类型，界面会提示接口不兼容；缺失字段或 `null` 不会自动补成零。

## 数据解释

额度优先读取 `rateLimitsByLimitId.codex`，该分组缺失时回退到兼容字段 `rateLimits`。程序检查 `primary` 和 `secondary` 的 `windowDurationMins`：

| 窗口分钟数 | 界面含义 |
| --- | --- |
| `300` | 5 小时额度 |
| `10080` | 每周额度 |
| 其他值或缺失 | 不归入上述两项 |

剩余百分比由 `100 - usedPercent` 得到，显示范围限制为 0～100%。恢复时间使用 `resetsAt` 的 Unix 秒时间戳，经 Windows 时区转换后显示。

可用重置次数来自 `rateLimitResetCredits.availableCount`，与 `credits` 数组条数分别处理。明细字段包括 `resetType`、`status`、`grantedAt`、`expiresAt`、`title` 和 `description`。

- `credits` 缺失或为 `null`：本次没有提供完整明细，保留缓存。
- 完整查询返回 `credits: []`：更新为空列表。
- `expiresAt` 明确为 `null`：显示“长期有效”；字段缺失则显示“未提供”。
- 已知类型、状态和精确匹配的常见说明转换为中文；其他自由文本保留并标注“服务端原文”。

最后成功查询时间和最后成功明细更新时间分别保存，便于分辨额度是否已更新、明细是否仍为旧缓存。

## 调度与异常

启动后立即执行完整查询，普通轮询默认间隔 3 秒。完整明细另外每 60 秒读取一次，即使用户将普通轮询间隔设得更长，也会到期获取明细；重置次数变化和手动刷新也触发完整查询。

后台串行执行查询，不建立查询队列。刷新间隔从上次查询结束后计算，等待使用条件变量和到期时间；修改设置会唤醒后台，按新间隔重新计算下一次查询时间。请求执行中收到的多次手动刷新合并为一个待执行的完整查询。

单次请求超时为 15 秒。进程退出、管道断开和请求超时会回收连接并重建；连续失败分别等待 3、6、12、24、60 秒，之后维持 60 秒。成功后恢复用户间隔；手动刷新可跳过当前重试等待。

失败时保留上次成功快照并提示“数据未更新”。尚未获得成功数据时显示“暂无数据”。字段类型不符、无效 JSON、方法或参数不兼容会显示明确错误，不用默认零值覆盖未知数据。

## 配置与构建

`Settings` 使用 EXE 所在目录的 `CodexUsage.ini`，键为 `[Settings] RefreshIntervalSeconds`。输入允许首尾空白，数值必须为 1～3600 的整数；文件缺失或读取内容非法时使用 3。保存失败会返回错误信息，界面提示后继续使用本次设置。

工程为 VS2022/v143、Windows 10/11 x64、C++17。Release 静态链接 MFC 和 C/C++ 运行库，使用 `/MT`；Debug 使用 `/MTd`。源码及资源按 UTF-8 编译，JSON 使用固定版本的 [nlohmann/json 3.11.3](https://github.com/nlohmann/json/tree/v3.11.3)，对应 MIT 许可证随源码保存在 [third_party/LICENSE.json](../third_party/LICENSE.json)。

## 验证范围

`scripts/test.ps1` 用于模型和配置测试；加 `-Integration` 会运行两组 GUI 集成测试。`tests/gui_validation.py` 通过模拟服务验证界面、配置保存、慢响应、刷新合并、错误恢复和退出回收，并可使用 `--soak-seconds 600` 记录至少 10 分钟的持续运行指标。`tests/gui_edge_cases.py` 另外验证非法输入、回车应用、INI 保存失败、空值、长间隔明细调度和连续失败退避。

模拟测试只能验证程序行为，不能代替服务端实际响应核对。当前开发环境中，沙箱拒绝访问本机 Codex 目录，真实账户查询与 CLI 对照尚未完成。已执行的构建和测试、CPU/内存/进程数量记录及未完成项统一写入 [验证记录](验证记录.md)。
